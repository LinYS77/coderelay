# CodeRelay 方案书（v0.3）

> 状态：三类 Provider 已实现，等待新验证码邮件端到端验收
> 日期：2026-07-30
> 部署：单文件 Linux 二进制，配置和 secret 外置

## 1. 最终需求边界

CodeRelay 只提供三类来源：

1. **TOTP Secret**：本地生成六位验证码；
2. **Outlook 四段式凭据**：
   `email----password----client_id----refresh_token`，读取 Outlook 验证码邮件；
3. **FlySMS 取件**：使用当前公开前端调用的 JSON 取件接口读取邮件验证码。

明确删除：

- Microsoft Graph；
- Microsoft App 注册和 Device Code Flow；
- delegated `Mail.Read`；
- MSAL token cache；
- Outlook 用户密码登录；
- Docker、Caddy 和多用户功能。

Outlook 四段式凭据中的 password 仅为兼容输入格式，导入时检查其存在后立即丢弃，不进入内存模型、不写入日志、不写入加密文件。

## 2. 实测结论

对一组脱敏处理流程中的 Outlook 凭据进行只读探测后确认：

- refresh token 可以换取 access token；
- token 的资源权限是 `https://outlook.office.com/*`，不是 Graph；
- Outlook REST 当前返回 200；
- IMAP XOAUTH2 登录成功；
- Inbox 可以 readonly 选择；
- `BODY.PEEK` 可以读取最新邮件头部；
- Graph 返回 401 是资源 audience 不匹配，不是邮箱无效。

因此 Outlook Provider 采用 IMAP，而不依赖已经不适合作为长期契约的 Outlook REST。

## 3. 技术选型

| 层 | 方案 |
|---|---|
| 语言 | Python 3.11+ |
| Web | FastAPI + Uvicorn |
| TOTP | PyOTP |
| Outlook OAuth | HTTPX 直接调用 v2 token endpoint，不使用 MSAL |
| Outlook Mail | Python `imaplib` + XOAUTH2，在线程中执行同步 IMAP |
| FlySMS | HTTPX JSON adapter |
| 配置 | TOML + 外置 secret files |
| 加密 | `cryptography` AES-GCM |
| UI | Jinja2 + 原生 CSS/JavaScript |
| 发行 | PyInstaller 单文件 Linux 二进制 |

完整 Graph SDK、MSAL 和相关依赖不再属于运行时依赖。

## 4. 架构

```text
调用方 / 浏览器
       │ HTTPS + API Bearer 或 HttpOnly Session
       ▼
CodeRelay FastAPI
       │
 ┌─────┼─────────────┐
 ▼     ▼             ▼
TOTP  Outlook IMAP  FlySMS
      │             │
      ├─ OAuth      └─ JSON API
      ├─ 加密凭据
      └─ readonly IMAP / BODY.PEEK
```

代码分层：

- `api.py`：统一 API 和响应模型；
- `services/code_service.py`：等待、超时、并发锁、短缓存；
- `domain/extractor.py`：六位码提取、新鲜度和歧义判定；
- `providers/totp.py`：本地 TOTP；
- `providers/outlook_imap.py`：OAuth token + IMAP；
- `providers/flysms.py`：FlySMS JSON；
- `infra/credential_store.py`：Outlook 加密凭据；
- `security.py`：API token、Argon2id、session；
- `ui/`：简洁前端。

## 5. Outlook Provider 设计

### 5.1 导入

命令：

```bash
coderelay outlook-import --config config.toml outlook_primary
```

输入格式：

```text
email----password----client_id----refresh_token
```

导入后加密 JSON 只包含：

```json
{
  "version": 1,
  "email": "...",
  "client_id": "...",
  "refresh_token": "..."
}
```

加密文件使用：

- AES-256-GCM；
- source ID 作为 associated data；
- 临时文件 + fsync + rename；
- 文件权限 0600；
- 默认拒绝覆盖，轮换时必须显式 `--replace`。

### 5.2 Token 刷新

请求 Microsoft v2 token endpoint 时只发送：

```text
client_id
 grant_type=refresh_token
 refresh_token
```

不请求 Graph scope，不发送邮箱密码。

响应处理：

- access token 仅保存在进程内并按过期时间缓存；
- 如果响应包含新的 refresh token，原子更新加密凭据；
- `invalid_grant` 映射为 `SOURCE_REAUTH_REQUIRED`；
- 429 尊重 `Retry-After`；
- 不记录响应正文或 token。

### 5.3 IMAP 读取

默认参数：

```text
Host: outlook.office365.com
Port: 993
Auth: XOAUTH2
Mailbox: INBOX
Mode: readonly
Body: BODY.PEEK[]<0.262144>
```

读取流程：

1. 建立 TLS IMAP 连接；
2. 使用 `user=<email>\x01auth=Bearer <access_token>\x01\x01`；
3. readonly 选择 Inbox；
4. 从最新序号向前读取有限数量邮件；
5. 用 MIME parser 提取 text/plain 和 text/html；
6. 忽略附件；
7. 通过 `not_before`、发件人、时间和验证码规则筛选；
8. logout，不标记已读。

## 6. 统一 API

```text
GET /api/v1/sources
GET /api/v1/codes/{source_id}
```

请求必须带：

```http
Authorization: Bearer <CodeRelay API Token>
```

邮件请求建议：

```text
GET /api/v1/codes/outlook_primary
    ?not_before=<触发验证码的 UTC 时间>
    &wait_seconds=20
```

`not_before` 是避免把上一封验证码误返回的关键参数。

统一错误：

- `401 AUTHENTICATION_REQUIRED`：CodeRelay API token 无效；
- `404 NO_FRESH_CODE`：没有符合新鲜度的验证码；
- `409 AMBIGUOUS_CODE`：多个候选无法判定；
- `424 SOURCE_REAUTH_REQUIRED`：Outlook refresh token 需要重新导入；
- `424 SOURCE_CREDENTIALS_INVALID`：上游凭据无效；
- `429 SOURCE_RATE_LIMITED`：上游限流；
- `502 UPSTREAM_SCHEMA_CHANGED`：FlySMS/上游格式变化；
- `504 UPSTREAM_TIMEOUT`：上游超时。

验证码响应统一设置：

```http
Cache-Control: no-store, private
Pragma: no-cache
```

## 7. 提取规则

默认候选：

```regex
(?<!\d)(\d{6})(?!\d)
```

优先级：

1. 自定义命名组 `(?P<code>...)`；
2. 发件人白名单；
3. `not_before` 和最大邮件年龄；
4. 主题、正文上下文关键词；
5. 最新邮件优先；
6. 同分歧义时失败，不随机返回。

如果来源邮件只有裸六位数字，可以设置 `generic_requires_keyword = false`，但应同时设置发件人和 `not_before`。

## 8. 安全边界

- password 字段不保存；
- Outlook refresh token 只存在 AES-GCM 文件和必要的进程内内存；
- TOTP secret、FlySMS token 不入 API URL；
- API token 只保存 hash；
- UI 密码使用 Argon2id；
- 不打印 access token、refresh token、邮件正文和验证码；
- 不渲染第三方邮件 HTML 到主页面；
- 服务只监听 loopback；
- 本项目不负责 TLS 代理配置；
- 所有真实凭据不得进入 Git、CI 或聊天记录。
