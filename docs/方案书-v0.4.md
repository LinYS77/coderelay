# CodeRelay 方案书（v0.4）

> 状态：无状态架构及真实三 Provider HTTP 验收已完成，等待公网部署
> 版本目标：0.3.0
> 生产域名：`https://2fa.077.li`

## 1. 产品定义

CodeRelay 是一个需要 Bearer Token 的无状态验证码解析 API，而不是凭据仓库。

调用项目在每次请求中提交本次上游凭据：

- TOTP Base32 Secret；
- `email----password----client_id----refresh_token` Outlook 字符串；
- `email---token---FlySMS pickup URL` 字符串。

CodeRelay 临时完成取码并返回 JSON。服务器不持久化调用方上游凭据。

## 2. 唯一取码接口

```http
POST /api/v1/code
Authorization: Bearer <CodeRelay API Token>
Content-Type: application/json
```

请求使用 `type` 区分：

```text
totp
outlook
flysms
```

成功通常只返回：

```json
{"code":"123456"}
```

Outlook refresh token 发生轮换时，可额外返回：

```json
{
  "code": "123456",
  "credential_update": {
    "refresh_token": "..."
  }
}
```

错误响应也可能携带 `credential_update`，调用方必须先更新自己的 secret manager。

## 3. 安全边界

### 服务持久化

只允许持久化：

- CodeRelay API Token 的 SHA-256 hash；
- 不含调用方上游凭据的策略配置。

禁止持久化：

- TOTP Secret；
- Outlook email/password/client ID/refresh token/access token；
- FlySMS email/token/pickup URL；
- 邮件正文；
- 验证码。

### 请求期内存

HTTPS 解密、JSON 解析和上游调用需要让凭据短暂进入内存。服务在请求结束时释放应用层引用，但 Python 不能承诺物理内存清零。

### 网络

- 只监听 `127.0.0.1:8787`；
- 公网仅通过现有 Caddy HTTPS；
- 取码 API 必须 Bearer；
- Token 和上游凭据不得进入 URL；
- Outlook/FlySMS 上游地址由服务器固定，调用方不能控制，防止 SSRF；
- access log 默认关闭；
- API 响应 `Cache-Control: no-store`。

## 4. 组件

```text
FastAPI POST /api/v1/code
        │
        ▼
StatelessCodeService.resolve(command)
        │ request-scoped provider
  ┌─────┼──────────────┐
  ▼     ▼              ▼
TOTP  Outlook IMAP   FlySMS JSON
```

### API 层

职责：

- Bearer 鉴权；
- discriminated JSON validation；
- 时区、等待时间验证；
- 最小成功 JSON；
- 统一错误 JSON；
- 不打印验证输入。

### StatelessCodeService

职责：

- 安全解析请求 credential；
- 创建请求级 Provider；
- 有限轮询和超时；
- 并发上限；
- 传播 Outlook token 轮换；
- finally 清理 command/provider 引用。

不包含：

- source registry；
- 跨请求 Provider；
- 结果 cache；
- credential store。

### Provider

每次请求创建并销毁。

Outlook：

- password 只验证存在，随后丢弃；
- refresh token 只用于 OAuth；
- access token 只在同一次长轮询中缓存；
- readonly Inbox；
- `BODY.PEEK`；
- token 轮换返回调用方。

FlySMS：

- 三段式内部字段必须相互一致；
- pickup URL 固定 HTTPS host/path；
- 固定 JSON API；
- latest/history/detail 有限请求。

TOTP：

- 标准 SHA1/30 秒/六位 Base32；
- `otpauth://totp` 可携带标准参数；
- `min_ttl` 防止返回即将失效的码。

## 5. 删除的旧设计

0.3.0 不兼容删除：

- `[[sources]]`；
- `GET /api/v1/sources`；
- `GET /api/v1/codes/{source_id}`；
- TOTP/FlySMS secret files；
- Outlook AES-GCM credential store；
- `outlook-import`；
- 网页密码、session 和 dashboard；
- 跨请求 access token/code cache。

删除旧接口比保留兼容层更安全，因为兼容层会继续诱导部署者把调用方凭据存进服务器。

## 6. 稳定性

- 单请求至少完成一次有限上游读取；
- `wait_seconds` 不截断已开始的读取；
- Provider 有独立硬超时；
- 总并发通过 semaphore 限制；
- API 每 IP + 每 Token 指纹限流；
- 429/503 尊重 `Retry-After`；
- `not_before` 防止旧码；
- 歧义时 409，不随机选码；
- Outlook token 轮换不因无状态而丢失。

## 7. 验收

自动测试：

- 三类请求 JSON；
- Bearer 必需且 query token 无效；
- 请求正文不出现在验证错误和日志；
- Outlook password 丢弃、轮换传播、readonly/BODY.PEEK；
- FlySMS 三段式一致性、固定域名和 SSRF；
- TOTP RFC；
- `not_before`、旧码和歧义；
- 请求结束 command/provider 清理；
- 无旧 source/UI/credential 命令；
- 单文件二进制 smoke。

真实验收必须通过 `POST /api/v1/code` 完成，并在结束后轮换聊天中暴露的所有测试凭据。
